# Changelog

All notable changes are recorded here. The build system combines the developer-owned
Major.Minor with a CI build number to form Major.Minor.Build.

## Next Version

- **The Project Tracking board now has a Refresh button.** Until now the only way to see work that had moved since you opened the query was to reload the page — which threw away everything you had set up: the branches you had collapsed, the discussions you had open, your sprint and tag filters, the order you had chosen, and where you were scrolled to. The new **⟳** button sits on the same line as the **＋**/**－** buttons but spaced apart from them, because it does something quite different. Pressing it re-reads the whole board from Azure DevOps and updates it in place, keeping all of the above exactly as you left it. It waits for any edit you have just made to finish saving first, so a refresh can never make a saved change look like it was lost. If the re-read fails, the board you were looking at stays on screen — it is still true, just older — and the button turns red to say so; pressing it then opens **Diagnostics** on the reason, and the press after that tries again. Note that this refreshes the AwesomeADO board only: Azure DevOps' own query grid, hidden underneath, is untouched.

- **@mentions in descriptions and notes now show the person's name.** Azure DevOps stores a mention as an internal identifier and only fills in the name in its own rendering, so mentions the extension had to render itself came out as an anonymous **@mention** — most obviously in every item description, and in any note Azure DevOps did not hand back ready-rendered. The board now gathers every mention across the whole query — descriptions and notes together — and looks all of those people up in one go, so the names appear without a lookup per mention and without slowing the board down. A mention nobody could be found for still reads as a neutral **@mention** rather than exposing an internal identifier, and if the directory cannot be reached the board simply keeps those placeholders and records why in **Diagnostics**.

- **A handful of @mentions stayed anonymous while the rest resolved.** Opening a notes panel while the board was still looking people up made that panel give up waiting and draw the mention as a placeholder — then remember the person as unnameable for the rest of the session, so it never came back. Whichever panel asked second lost, which is why it looked random and why the same person could show correctly in one place and not another. Lookups that overlap now wait for each other instead of racing, a lookup that never reached Azure DevOps is tried again rather than remembered as a dead end, and a mention in a note **you** have just written is now resolved too. **Diagnostics** also names the exact identifiers that could not be resolved and says whether they will be retried, so an anonymous mention can be traced instead of guessed at.

- **Screenshots pasted into a note or a description now actually show up.** They were being rendered as an empty box: Azure DevOps refers to an embedded picture by an internal id alone, and the extension only accepted a fully written-out web address, so it threw the reference away and kept the empty frame. Those references are now turned into the same attachment request Azure DevOps itself makes, so the picture loads exactly as it does in Azure DevOps — while anything that is not a real image address is still refused.

- **Notes on the Project Tracking board now read in a softer, warm tone.** A note used to be printed in the same full-strength colour as the item's own details, so an expanded row was a wall of identical text. Notes are now tinted a gentle yellow-brown that is derived from whichever theme you are using, so they sit back from the item's title while staying perfectly readable on the light, dark, blue and "Follow Azure DevOps" themes alike.

- **Every item on the Project Tracking board now shows its notes — the Discussion from Azure DevOps — right under its row.** In front of each title there is now the item's own type icon, in the type's Azure DevOps colour and sized to match the title, and clicking it opens that item's notes. The icon tells you where the notes are **before you click**: it is **grey** when the item has no discussion at all, **dimmed but coloured** when there is something to read, and **full colour** while you are reading it — so one look down the left edge of the board is enough. (Azure DevOps only counts an item's comments in total, so an item whose notes are all older than your window starts out coloured and settles to grey once you have opened it. A note that failed to load never turns an icon grey — that would claim there is nothing there when nobody could tell.) Notes are only fetched when you first open an item, so a large board still loads at the same speed. Each note reads as **who wrote it, when, and what they said**, newest first, and an expanded list shows the two most recent days that have notes — all of them, so a busy afternoon is never cut in half. How far back a board looks is the **Updates window (weeks)** you set on the query's binding. A small **"+ Add note"** link sits above the list, and if a note is one **you** wrote, your own name is clickable and opens it for correction in place. Nothing appears on the board until Azure DevOps has accepted it, so a note that failed to save never looks saved.

- **Descriptions and notes now render the way Azure DevOps shows them.** An item's description used to be flattened to plain text before it was ever displayed, so bullet lists, bold, links and headings were thrown away and pasted screenshots vanished entirely. Descriptions and notes now render properly, **pictures pasted into them show up**, and an **@mention** shows the person's name instead of an internal identifier. Anything that could run code — scripts, embedded frames, click handlers, `javascript:` links — is stripped before it reaches the page.

- **A note that fails to load now says what went wrong.** Notes that could not be read reported only "no response from background" and left nothing at all in the **Diagnostics** log to go on. Every notes request is now recorded on arrival and again with its result — how many pages were read, what Azure DevOps answered, and whether it recognised who you are — and a request the extension cannot make sense of is now answered with the exact field that was wrong instead of being dropped in silence. If the extension was updated or reloaded while an Azure DevOps tab stayed open, the failure now says so and tells you to reload the tab, rather than looking like a network problem.

- **The "Waiting" row is gone from Azure DevOps → Marker tags.** Nothing in the extension ever acted on that tag or comment token, so the section now lists only the conditions that are actually used: blocked (internal), blocked by another team, and interrupt. Any value you had typed into the Waiting row is dropped; the other three rows keep what you configured.

- **Collapsed rows on the Project Tracking board stay collapsed.** Anything that redrew the tree — dragging an item to a new position, changing the sort order, or switching the sprint or tag filter — sprang every branch you had closed back open, so a board you had narrowed down to the part you cared about kept unfolding itself. Each row now remembers whether you left it open or closed, and only the rows you actually collapsed come back collapsed.

- **Dragging an item to a new position now works on boards Azure DevOps refused to re-order.** Azure DevOps only re-orders items that already hold a place on the team's backlog, so a drop was rejected outright — every time, no matter how often you retried — when the item had never been ranked, or when its parent is a work item of its own kind (a User Story under a User Story, a Feature under a Feature), which Azure Boards does not order at all. The refusal came back as the misleading _"TF400486: … you or another user has modified, removed, or re-parented items"_, which reads like somebody else had edited the item. The extension now recognises that refusal, writes the item's backlog rank itself — dropping it midway between the two items you dropped it between, or spacing out the whole group when there is no room left — and the row settles where you put it. The **Diagnostics** log records Azure DevOps' exact words, a plain-English explanation of what they really mean, and which items were re-ranked. A move that changed an item's **parent** but then failed is also no longer hidden: the board now shows the new parent, because that part really did happen in Azure DevOps.

- **Clicking the "Couldn't save" badge now shows you what went wrong.** It opens the extension's **Diagnostics** log with the **Errors only** filter already switched on, so you land on the failures instead of hunting for them among the newest routine lines. If a Diagnostics tab is already open it is reused and switched over in place, rather than piling up another one. The badge still goes quiet once you have followed it — and still comes straight back if something else fails.

- **Importing a configuration file now updates the page you are looking at.** The file was read and saved correctly, but the **Azure DevOps** tab and the **query bindings** form kept showing the configuration it had just replaced until you closed and re-opened the options tab — and worse, the next edit you made in either of them saved those old on-screen values back over the import. Both now re-read the stored configuration the moment an import finishes.

- A **marker tag** you type is now saved against the box you typed it in, and nothing else. Saving a marker used to re-read all eight boxes and write the whole set, so anything that disturbed the section's fields — a value the browser restored into the wrong box after a restart, or rows left showing the old configuration after an import — could be written under a neighbouring condition and quietly replace its tag. Each edit is now stored as a change to that one field, with every other condition carried over from the last saved values.

- The **Work item type hierarchy** section is quicker to read and harder to get wrong. Each row now shows just its child types plus a small **`+`** button; the picker only appears once you click it. Because the **Work item types** table above is ordered parent-to-child, a row is now only offered the types listed **below** it — never itself and never anything above it — so the hierarchy always runs downwards, and the **last type has no `+` at all** and simply reads **Leaf Item**. Types that already sit under the **same parent** are siblings, and siblings are no longer offered to each other: if _User Story_ and _Bug_ can both be created under _Feature_, neither can be made a child of the other.

- The **Work item types** mapping table now uses that same **`+`** button. Each column cell shows only the states you have placed in it until you click `+` to pick another, so a five-column table is no longer five "Add state…" boxes wide, and the `+` disappears once every state of that type has been placed.

- The rows under **Item ETA fields** and **Marker tags** no longer sit flush against each other, so the border and focus ring around each box is fully visible instead of being clipped by the row beneath it.

- **Importing a configuration file** no longer reports success when it quietly threw half of the file away. Anything it cannot use — a setting with a value it does not recognize, an enhanced query that names no view, a view setting that is not text, a file that carries no AwesomeADO version stamp or one written by a newer build — is now **named in red** on the Import/Export card and recorded in the **Diagnostics** log, instead of being replaced by a default behind a cheerful "Imported your configuration." Everything the file _does_ get right is still imported: one bad value now costs you that one value rather than the whole file, and a setting the file leaves out (or gets wrong) keeps whatever you have configured today instead of being reset to a default the file never asked for.

- The **blocked / interrupt / waiting tag** vocabulary configured under **Azure DevOps → Marker tags** is now actually saved. Every edit was accepted, reported as saved, and then lost on the next reload — and it was silently dropped when importing a configuration file too.

- The five **column title boxes** in the **Work item types** table now line up along the bottom of the header, instead of stepping up and down with the length of the description printed above each one.

- The Azure DevOps options now let you describe your **work item type hierarchy**. A new section under **Work item types** gives every configured type a row listing the types that can be created underneath it. Add them from a searchable picker, drag them to reorder, and the **first one is highlighted** — that is the type created when you add a child in a view. A type with nothing under it is marked **Leaf Item**. The picker only offers types that cannot loop back to the one you are editing, so the hierarchy can never fold in on itself (an imported configuration file containing a loop is cleaned up on load too). The **Work item types** table also now spells out what each of its five fixed columns means to the views — _work has not started yet_, _someone is working on it_, _not completed, but the developer is not actively spending time on it (waiting for something before continuing)_, _item is resolved (completed)_, and _item is abandoned (removed)_ — shown above each column title and repeated when you hover the title, so renaming a column no longer hides what it actually drives.

- Tidier, roomier **Project Tracking** board. The **"Saving…" / "Couldn't save"** indicator now sits in the header's top-right corner **next to the sort glyph** instead of on a row of its own, and that corner's height is reserved — so the board no longer jumps up and down every time a save starts, finishes or fails. The **"Couldn't save" badge can now be clicked away** once you have read it (it comes straight back if something else fails). The left and right margins are about **60% narrower**, so item titles get the width instead of the page edges. And the **assignee dropdown** no longer grows a horizontal scrollbar when someone has a long name or email address — those are trimmed with an "…" and shown in full when you hover them.

- A **failed save** on the **Project Tracking** board is now impossible to miss. Because every control on the board only updates once Azure DevOps accepts the change, a rejected save used to leave the screen looking exactly as it did before — with nothing but a faint line of small red text in the header corner to say an edit had been lost. It is now a **solid red alert badge** with a warning icon that pulses briefly when the failure happens, and **hovering it tells you why the save was rejected** (Azure DevOps' own explanation) and points you at the Diagnostics log. Screen readers are told about it immediately rather than waiting for a pause.

- Failures while **re-ordering** items now say what actually went wrong. Azure DevOps explains its refusals ("this work item does not exist", a rule violation, an item edited by someone else in the meantime) and that explanation is now recorded in the **Diagnostics** log instead of a bare "HTTP 400". A move that the extension itself could not even attempt now names the missing piece — the team that is not configured, the URL it could not build, or the field that was wrong — rather than reporting an unexplained "no response". If the background worker has no answer at all, the log now says so plainly and reminds you that reloading the extension is the usual fix after an update.

- Items on the **Project Tracking** board can now be **re-ordered by dragging them**. Grab a row by its **title** (the pointer turns into a grab hand over it) and drop it wherever you want it — a line shows exactly where it will land, and if you drag it onto a different parent that parent is highlighted too, so you can see the re-parent before you let go. Dropping saves the new order to Azure DevOps using ADO's own backlog-ordering, and moving an item to a different parent re-parents it there as well. An item can only be dropped at the level it came from, so a parent is only ever re-ordered among its own peers and never becomes somebody else's child. Dragging is only offered while the board is sorted **By Importance** — under any other order the item would just be sorted straight back out of where you dropped it — and the header's **⇅** turns a faint red to tell you so (hover it for the reason). The same goes when no team is configured, since Azure DevOps keeps the backlog order per team. The move saves through the same queue as your status, ETA and assignee edits, so the row settles into its new place once ADO accepts it and a rejected move is reported by the "Couldn't save" indicator rather than leaving the board showing something that was never saved. Sorting a move out while a sprint or tag filter is hiding rows still puts the item exactly where you aimed once you clear the filter.

- The **Project Tracking** board now shows how it is sorted, and lets you change it without leaving the page. A discrete **⇅** in the header's top-right corner names the ordering in force when you hover it (_By Importance_, _By Title_, _By ETA_), and clicking it opens the same list of orders the query's **Items ordering policy** setting offers. Picking one **re-sorts the whole tree instantly** — every level plus the rolled-up children popup — without re-reading the query from Azure DevOps. The pick applies to the board you are looking at; the query's configured policy stays the order every board opens on.

- The **Project Tracking** board now honors two settings it had been ignoring. Items are **ordered** by the binding's **Items ordering policy** — by importance (Azure DevOps' backlog rank, most important first), by title (a–z), or by ETA (earliest first, undated last) — at every level of the tree and inside the rolled-up children popup. Items that reached the **resolved** column (the one before Removed) also disappear once they have been sitting there longer than **Hide resolved after (days)**, so finished work stops crowding out what is still in flight. The age is measured from when the **state** last changed, so commenting on or re-tagging a finished item no longer brings it back for another few days; an item still keeps its place while unresolved work sits beneath it, and the rolled-up "done / total" badge counts only the children the board is actually showing.
- The expand/collapse **triangles** on the **Project Tracking** board no longer grow oversized after using the **expand-all**/**collapse-all** buttons. The triangles stayed enlarged for the rest of the session and stopped flipping when a row was toggled by hand.
- The assignee picker's **search of all of Azure DevOps** now finds the people it was missing. Anyone the organization did not already know about — exactly who you search for when they are not on the project yet — was being discarded before the list was drawn, even though Azure DevOps had returned them. While a search is running the picker now also shows a **spinner** next to "Searching Azure DevOps…", so a slow answer reads as "wait a moment" instead of "nobody found". A failed search is no longer disguised as "No people found." either — the **Diagnostics** view records exactly why one came back empty (rejected request, expired sign-in, or no connection).
- The **assignee picker** on the **Project Tracking** board now behaves like an ordinary dropdown: it opens with the cursor already in the search box, the up/down arrow keys move the highlight through the list, and Enter picks the highlighted person — so a reassignment can be done without touching the mouse. Every person it offers now also shows their **Feature Crew tag** (or "??" when they have none), so you can tell two same-named people apart and see which crew you are assigning to before you pick.
- The **assignee picker** on the **Project Tracking** board now works. Clicking an assignee opens a list of everyone already working on the project, so the usual reassignment is a single click with nothing to type. Type two or more characters to search **all** of Azure DevOps for anyone else, matched on name or email. The picker also closes properly now — clicking anywhere outside it, or pressing Escape, dismisses it — and it tells you what it is doing ("Searching Azure DevOps…", "No people found.") instead of showing an empty box.
- Picking someone in the **assignee picker** now actually **reassigns the work item** in Azure DevOps. Previously the choice only updated the Feature Crew roster and the item kept its old owner. The change saves through the same queue as status and ETA edits — the name updates once Azure DevOps accepts it, and a rejected save is reported by the board's "Couldn't save" indicator instead of leaving an owner on screen that was never saved. This works on the tree rows, the **TechLead** on the header, and the rows inside the rolled-up children popup.
- The **ETA date picker** now opens fully visible when you click an ETA inside the rolled-up children popup on the **Project Tracking** board. That popup is only as tall as its rows, so the picker used to be clipped away to nothing behind it — leaving stray scrollbars instead of a date field.
- The ETA date picker's **calendar button** now shows a hand cursor, so it is obvious it can be clicked.
- The **calendar** the browser opens from the ETA date picker now matches your theme instead of always opening white, and its calendar button is clearly visible on dark themes. Scrollbars inside the enhanced view follow the theme too.
- **"No ETA"** now reads noticeably fainter than a real ETA date on the **Project Tracking** board, so the items that actually have a target date stand out.
- Popups on the **Project Tracking** board (the ETA date picker, the status menu, the assignee picker, and the rolled-up children list) no longer open half off-screen when the control they belong to sits near the edge of the window. They now slide back into view, and flip above the row when there isn't room below.
- The **ETA** date picker on the **Project Tracking** board is no longer borderless under the **Follow ADO** theme: the popup and its date field now keep a visible outline on every theme. The **Clear** button also got a subtle border and now highlights when you hover over it.
- On the **Project Tracking** board, a save that Azure DevOps rejects is no longer silent. The "Saving…" row now turns into **"Couldn't save N change(s)"** so a lost edit is obvious instead of looking like a slow one. Making two quick edits to the same item (for example its status and then its ETA) now also saves **both** — previously the second edit was discarded because it still carried the item's pre-save revision.
- Fixed a bug where a setting that had not changed recently could silently revert to its default for the rest of a tab's life. If a synced value changed at the exact moment AwesomeADO was loading your settings, every **other** setting was left at its default until something else changed.
- Fixed **board column titles** so two columns can never end up with the same name. Renaming a column to a title another column already uses (for example renaming the first column to "Done") previously produced two columns called "Done", which silently broke the completed-children count and the status colors on the Project Tracking board.
- **Importing a configuration file** now refuses a file that is not a complete AwesomeADO configuration, instead of resetting every setting and deleting every query binding and reporting success. Only files containing both sections are accepted.
- Fixed a bug on the **Project Tracking** board where a single failed roster sync could stop every later tag or assignee change from saving, and leave the "Saving…" indicator showing a save that would never finish.
- **Clearing the Diagnostics log** now tells you when it fails, instead of leaving the entries on screen with no explanation.
- **View Log** and **Options** now open a fresh options tab when the remembered one has been navigated elsewhere, instead of silently stealing focus and doing nothing. The diagnostics log also no longer records your **query names** — only their identifiers — so an exported log carries no team, project, or customer names.

- The **Project Tracking** sprint picker now keeps its color cue when the dropdown is **closed**: the collapsed box shows the selected sprint in orange (past), your theme's accent blue (future), or bold (current), instead of only showing those colors while the list is open.

The next sprint is now labelled simply **Next - _name_** instead of _Next sprint - name_.

Everything below that level is rolled up onto the deepest row as a compact **"done / total" badge** (e.g. _1 / 3_), tinted with a discrete wash of the last configured work item type's color. Click the badge to open a popup listing each of those children as **{assignee} {title} {ETA}**, with a type icon that opens the item in Azure DevOps. The assignee picker and the ETA editor work exactly as they do on a tree row, and the rollup respects the active sprint and tag filters, so its count always matches what the board is showing.

Pick a date to save it to that item type's configured ETA field, or use the **Clear** button to reset the item back to _No ETA_. An **overdue** ETA is shown in **bold**.
- On the **Project Tracking** board, each assignee's **Feature Crew tag** pill is now **editable**: click it to move the person onto another tag already in use, or add a brand-new one (max 15 characters, no spaces, and no duplicate of an existing tag). Your pick is saved back to the roster right away, and because a new tag is applied to that person the moment it's created, the board never accumulates tags that aren't assigned to anyone. The tag pill was also tightened up so it lines up with the status badge height.
- Fixed a bug on the **Project Tracking** board where a work item's **status** dropdown kept showing the old list of choices after you moved the item to a new status; the menu now always lists the states you can move to from the item's current status.
- On the **Project Tracking** board, each assignee now shows their **Feature Crew tag** as a colored pill next to their name (a distinct bright color per tag), and a new **tag filter panel** appears above the tree once the roster loads. Click one or more tags to narrow the board to items assigned to people wearing **any** of the selected tags (an OR filter), combined with the sprint filter; ancestors of matches stay visible so nothing is orphaned. A neutral **"??"** pill represents people who don't have a tag yet — both on the row and in the filter panel.
- The hidden **Feature Crew** roster item on the **Project Tracking** board now saves its description as **Markdown**, so the crew list renders one person per line underneath the _Feature Crew_ heading instead of collapsing onto a single line next to it.

- The **Project Tracking** board's Feature Crew roster now saves reliably the first time on projects whose Azure DevOps process blocks creating a work item directly in the **Removed** state: AwesomeADO now creates the hidden roster item in its default state and then immediately marks it Removed, instead of failing the create.

- When AwesomeADO can't save the **Project Tracking** board's Feature Crew roster back to Azure DevOps, the Diagnostics log now records the **specific reason** — the HTTP status code and Azure DevOps' own error message (e.g. a permission error or a process rule blocking the write) — instead of a generic "write failed", so the failure is easier to understand and report.
- On the **Project Tracking** board, the header breadcrumb now shows the query's **parent-folder trail** from Azure DevOps (e.g. _Razvan's Team / Project Views_) instead of the query name, so you can see where the query lives at a glance. It shows the two nearest folders — the query's parent and its parent's parent — separated by a forward slash to match Azure DevOps, and **each folder is a link** that opens that folder's contents in Azure DevOps. The trail comes from the query's Azure DevOps metadata, so it stays correct even on ADO's newer breadcrumb bar.
- On the **Project Tracking** board, a **"Saving…" indicator** now appears on its own row above the sprint picker whenever your status changes are being written back to Azure DevOps. It shows an animated spinner and a live count of in-flight saves (e.g. _Saving 2 changes…_) and disappears once every change has been saved, so you always know when the board is done persisting your edits.
- On the **Project Tracking** board, the sprint pill (shown per row when the filter is off) now only appears for items assigned to a real sprint. An item parked on the iteration **root** (no specific sprint) shows no pill instead of a badge for the root node.
- The **Project Tracking** sprint dropdown is now populated from your configured team's actual sprints instead of only the sprints seen on the board. It shows a window centered on the **current** sprint — a few past and a few future sprints, bounded by your past/future sprint-count settings — with clear relative labels (**Current - _name_**, **Next - _name_**, **Previous - _name_**, **_2_ sprints ahead - _name_**, **_2_ sprints ago - _name_**), and it opens pre-selected on the current sprint. Leave any box blank if your team does not use that signal. Your entries are synced and included in configuration export/import.

Choosing Light, Dark, or Blue pins that theme across the view no matter what theme Azure DevOps is using, while **Follow ADO** keeps matching Azure DevOps' own light/dark theme. Changing the theme re-themes an open enhanced view right away.

Picking a new status queues the save so rapid changes are written back to Azure DevOps one at a time in order (never racing), and the badge updates to the new Status as soon as it commits. Status colors are also more intuitive and still theme-aware — **Waiting** leans yellow and **Removed** leans red.

Every control — status, sprint picker, expand/collapse, twisties — follows your Azure DevOps light/dark theme. ## 0.1 - Initial scaffolding and basic functionality

- Initial release of the AwesomeADO MV3 extension for Chrome and Edge, including CI/Release pipelines with an immutable release workflow and changelog-validated versioning, and the AwesomeADO icon (an Azure DevOps work-item card with a checkmark and sparkle) shown in the browser toolbar and extensions list.
- Added per-query bindings: each Azure DevOps query can be bound to a view (Sprint View or Project Tracking) with its own settings, so the same view can be configured differently per query. Bindings sync across your devices.
- Added an "Enhance with AwesomeADO" button to the Azure DevOps top bar that appears on any saved query page (bound or not) and opens a popup menu aligned under it. The button shows the extension icon (its purpose stays available as a tooltip and to screen readers) and sits inside the Azure DevOps top-bar command bar alongside ADO's own icons, styled to match them (flat square button with the same hover highlight). On an unbound query the menu offers Options and "Enable Enhanced View" (which opens the options page to bind that query); on a bound query the menu lets you switch that query between its bound view (e.g. Sprint View) and ADO's Standard View, open Options, or "Disable Enhanced View" to remove the binding. The per-query view choice is remembered, synced across your devices, and overrides the global default view.
- Unbound Azure DevOps queries are always left on ADO's own view — the extension only injects its button and never replaces the page until you bind the query. The global Default view applies only to bound queries, and query-page enhancement hides only the content below the top breadcrumb bar, keeping ADO's breadcrumb navigation visible.

The options page header shows the AwesomeADO icon.

Each query can be given an Enhanced View Type, saved, or deleted (unbound), so several queries can each be managed independently.
- The options page detects open ADO Query tabs regardless of which tab is focused, so opening the options tab in the foreground no longer hides the active query's organization and project. It also shows a visible error message when it fails to load or hits an error later, instead of failing silently.
- Auto theme reads Azure DevOps' theme color token instead of the page's white loading fallback, so a Dark ADO account is no longer misread as Light (no options-page white flash).
- The button's "Options" and "Enable Enhanced View" menu items reliably open the options page; failures to open it are now reported instead of being silently ignored.
