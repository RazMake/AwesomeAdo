# Changelog

All notable changes are recorded here. The build system combines the developer-owned
Major.Minor with a CI build number to form Major.Minor.Build.

## Next Version

- The **Project Tracking** sprint dropdown now reads at a glance: past sprints (_Previous_, _2 sprints ago_, …) are shown in orange, future sprints (_Next_, _2 sprints ahead_, …) in your theme's accent blue, and the **Current** sprint is bold. The next sprint is now labelled simply **Next - _name_** instead of _Next sprint - name_.

- On the **Project Tracking** board, each item's **ETA** is now **editable**: it shows in a muted color, turns to a hand cursor on hover, and clicking it opens a small date picker. Pick a date to save it to that item type's configured ETA field, or use the **Clear** button to reset the item back to _No ETA_. An **overdue** ETA is shown in **bold**.
- On the **Project Tracking** board, each assignee's **Feature Crew tag** pill is now **editable**: click it to move the person onto another tag already in use, or add a brand-new one (max 15 characters, no spaces, and no duplicate of an existing tag). Your pick is saved back to the roster right away, and because a new tag is applied to that person the moment it's created, the board never accumulates tags that aren't assigned to anyone. The tag pill was also tightened up so it lines up with the status badge height.
- Fixed a bug on the **Project Tracking** board where a work item's **status** dropdown kept showing the old list of choices after you moved the item to a new status; the menu now always lists the states you can move to from the item's current status.
- On the **Project Tracking** board, each assignee now shows their **Feature Crew tag** as a colored pill next to their name (a distinct bright color per tag), and a new **tag filter panel** appears above the tree once the roster loads. Click one or more tags to narrow the board to items assigned to people wearing **any** of the selected tags (an OR filter), combined with the sprint filter; ancestors of matches stay visible so nothing is orphaned. A neutral **"??"** pill represents people who don't have a tag yet — both on the row and in the filter panel.
- The hidden **Feature Crew** roster item on the **Project Tracking** board now saves its description as **Markdown**, so the crew list renders one person per line underneath the _Feature Crew_ heading instead of collapsing onto a single line next to it.

- The **Project Tracking** board's Feature Crew roster now saves reliably the first time on projects whose Azure DevOps process blocks creating a work item directly in the **Removed** state: AwesomeADO now creates the hidden roster item in its default state and then immediately marks it Removed, instead of failing the create.

- When AwesomeADO can't save the **Project Tracking** board's Feature Crew roster back to Azure DevOps, the Diagnostics log now records the **specific reason** — the HTTP status code and Azure DevOps' own error message (e.g. a permission error or a process rule blocking the write) — instead of a generic "write failed", so the failure is easier to understand and report.
- On the **Project Tracking** board, the header breadcrumb now shows the query's **parent-folder trail** from Azure DevOps (e.g. _Razvan's Team / Project Views_) instead of the query name, so you can see where the query lives at a glance. It shows the two nearest folders — the query's parent and its parent's parent — separated by a forward slash to match Azure DevOps, and **each folder is a link** that opens that folder's contents in Azure DevOps. The trail comes from the query's Azure DevOps metadata, so it stays correct even on ADO's newer breadcrumb bar.
- On the **Project Tracking** board, a **"Saving…" indicator** now appears on its own row above the sprint picker whenever your status changes are being written back to Azure DevOps. It shows an animated spinner and a live count of in-flight saves (e.g. _Saving 2 changes…_) and disappears once every change has been saved, so you always know when the board is done persisting your edits.
- On the **Project Tracking** board, the sprint pill (shown per row when the filter is off) now only appears for items assigned to a real sprint. An item parked on the iteration **root** (no specific sprint) shows no pill instead of a badge for the root node.
- The **Project Tracking** sprint dropdown is now populated from your configured team's actual sprints instead of only the sprints seen on the board. It shows a window centered on the **current** sprint — a few past and a few future sprints, bounded by your past/future sprint-count settings — with clear relative labels (**Current - _name_**, **Next - _name_**, **Previous - _name_**, **_2_ sprints ahead - _name_**, **_2_ sprints ago - _name_**), and it opens pre-selected on the current sprint. The sprint-loading logic is shared, so other sprint-filtering views can reuse it.
- The Azure DevOps options tab has a new **Marker tags** section where you tell AwesomeADO which Azure DevOps **tag** your team uses to mark an item as **Blocked (internal)**, **Blocked by another team**, **Interrupt**, or **Waiting**, along with the **comment tag** your team writes in an item's comments for each one (defaults: `[BLOCKED]`, `[ACCEPTED]`, and `[WAITING]`). Leave any box blank if your team does not use that signal. Your entries are synced and included in configuration export/import.
- The **board columns** on the Azure DevOps options tab are now a fixed set of five — **In Queue**, **In Progress**, **Waiting**, **Done**, and **Removed** — so every team maps its states onto the same, consistent workflow. You can still **rename** each column's title to match your own terminology, but columns can no longer be added or removed. Existing custom column titles are preserved.
- On the **Project Tracking** board, status badge colors are now consistent across every work item type: a status is colored by its position in your board columns rather than its type or name — the 1st column is gray, the 2nd blue, the 3rd yellow, the 4th green, and the 5th red — so the same board column always looks the same everywhere. The "done" (green) and "removed" (red) columns use a matching, brightness-contrasted text so they stand out at a glance, and all the tints stay theme-aware.
- The **Theme** you pick in Options (Follow ADO, Light, Dark, or Blue) now applies to the whole enhanced view and every control in it — not just the options page. Choosing Light, Dark, or Blue pins that theme across the view no matter what theme Azure DevOps is using, while **Follow ADO** keeps matching Azure DevOps' own light/dark theme. Changing the theme re-themes an open enhanced view right away.
- On the **Project Tracking** board, each item's status now shows your own board column (its **Status**, e.g. _Active_ or _Done_) rather than the raw Azure DevOps state, so the badge always reads in your team's terms. Picking a new status queues the save so rapid changes are written back to Azure DevOps one at a time in order (never racing), and the badge updates to the new Status as soon as it commits. Status colors are also more intuitive and still theme-aware — **Waiting** leans yellow and **Removed** leans red.
- Polished the **Project Tracking** board header and controls to fit your Azure DevOps theme more closely: the sprint filter and the expand/collapse buttons now sit on the same row as the title and **TechLead** (vertically aligned), the collapsed tree twisty no longer shows a colored/emoji box (it now matches the expanded triangle), the sprint dropdown is populated from the sprints seen across the board, each item's **status** badge is tinted by its specific state (subtle, theme-aware) and its change menu lists the other states as colored badges without repeating the current one, and the **?** description button is a round, theme-blue badge with a light ring.
- The **Project Tracking** board has a refreshed, fully theme-aware layout: the title sits at the top with the **TechLead** and the epic's **ETA** together on the line beneath it, the sprint control is now a compact **filter icon beside a sprint dropdown** (defaulting to the team's sprints), the title area reads as a subtle panel instead of an underlined row, and child items are indented far less with a discrete vertical guide line connecting them to their parent. Every control — status, sprint picker, expand/collapse, twisties — follows your Azure DevOps light/dark theme. Each item's **status** is now an editable control: click it to pick a new application state from your configured board columns, and the change is saved back to Azure DevOps immediately.
- The **Project Tracking** board is cleaner: the tree no longer repeats the epic as its top row (the epic is already summarized in the header) and starts directly with the epic's children, and the thin divider lines between rows are gone.

- The people picker in the **Project Tracking** view is now simpler: the assignee shows as plain, clickable text (just the person's name, no avatar, border, or box) that turns into a hand cursor on hover and opens the picker when clicked. The shared view controls also now follow Azure DevOps' light/dark theme instead of using fixed colors.

- The **Project Tracking** view now keeps a project's **Feature Crew** roster up to date automatically. When the board loads it gathers everyone assigned across the tree and records them in a single dedicated work item (titled _Feature Crew_, kept in the **Removed** state so it never shows up in your normal queries, and linked to the epic as **Affected By**); its description is a simple markdown list of `alias (full name) \`tag\``, one line per person. The item is created once if it does not already exist and reused afterward (matched by title, type, and its link to the epic, so it is never duplicated), existing people and any tags you added by hand are preserved, and anyone you assign inline in the view is added to the roster right away.
- The **Project Tracking** view now renders a proper tracking board for a query bound to a **tree (work item links) query** that has a single root of your first configured work item type (usually Epic); any other query shows a clear message explaining what it needs instead. The board titles the page with the epic's title (in its type color), shows the epic's assignee as **TechLead**, and lists every item as an expandable/collapsible tree with type-colored titles and their state. A **sprint dropdown with an on/off filter toggle** beside it filters the tree to one sprint when lit, or — when off — disables the dropdown and shows each item's sprint as a pill on its row. A **?** after each title opens a description panel that starts with the item's Created and Last Modified dates (and who by), every date shows the exact time in PST on hover, the assignee can be changed inline, and each row shows an **ETA** on the right that counts down and colors by how close it is.
- Work item types on the Azure DevOps options tab are now **ordered parent-to-child**, with the top-most parent first. Each row has a grip **drag handle** you can use to drag it into position, and while you drag an **insertion line** previews exactly where the row will land (above or below the row you are hovering). The card explains that the order defines the hierarchy, the read-only **Item ETA fields** list stays in the same order as the table, and the order is preserved when you save, export, and import your configuration.

- The Azure DevOps options tab now has a **Past sprints count** setting, right after Future sprints, for how many sprints before the current one the sprint picker offers (a whole number from 0 to 6, default 0 — only the current and future sprints are shown). It saves as you change it, forces out-of-range values back into their bounds, and syncs across your devices.
- The **Project Tracking** view now has per-query settings on the Query Enhancement Configuration card: an **Items ordering policy** dropdown (order items by importance, title, or ETA — default _by importance_), an **Updates window** in weeks (1–52, default 2), a **Hide resolved after** value in days (0–3650, default 4), and a **Recent changes window** in hours (default 24). Each field shows a short explanation, seeds its default when left unset, forces numbers back into their range, and keeps the ordering choice only while it is still one of the offered policies; the values save with the binding and sync across your devices.
- The Azure DevOps options tab now has an **Item ETA fields** section that maps each work item type to the Azure DevOps date field used as its ETA. It lists one read-only row per work item type you configured in the table above, each with a dropdown of only the date fields that exist on that type (loaded from your signed-in Azure DevOps session, excluding platform-managed lifecycle dates such as Created, Changed, Resolved, and Closed so only real target dates are offered); the ETA is set per type with no shared default, an already-saved choice stays selected even before the field list loads, and it syncs across your devices.
- Added an **Azure DevOps** tab to the options page and moved the read-only ADO Configuration panel (organization and project) there from Appearance, which now keeps only Theme and Default view. The new tab adds three synced-per-device settings: a searchable **Current team** picker populated from the detected organization/project, a **Future sprints** count (a whole number from 1 to 12, offered in the sprint picker in addition to the current sprint), and an **Area paths** list where each row has an area-path field with autocomplete (matching any part of the path) plus a label that defaults to the path's last segment, with controls to add and delete rows. Each setting saves as you change it.
- Added a **Work item types** mapping table at the end of the Azure DevOps options tab. Its columns are your team's own application states (user-defined — rename, remove, or add up to six), and each row is one work item type, picked from a searchable list of the organization/project's types shown with their Azure DevOps icon and color. In each cell you add that type's ADO states from a searchable field; a state can sit in only one column, and the first state in a cell is highlighted as that column's primary value (the one written back to ADO). Any ADO state you do not place falls back to the first column (treated as "not picked up"). Columns, rows, and their choices sync across your devices and save as you edit.
- The extension now treats itself as configured only once the Azure DevOps settings are complete (a current team, at least one area path, at least one board column, and at least one work item type with a mapped state). While a query is bound but the configuration is incomplete, the enhanced view is held back and the query stays on Azure DevOps' own view, the options page shows an error banner explaining why, and the AwesomeADO button's menu hides the view-swap options until you finish the setup.
- The Azure DevOps options tab now loads the detected organization's **teams** and **area paths** using your signed-in Azure DevOps session, so the **Current team** picker and **Area paths** autocomplete offer real suggestions with no extra sign-in or permission prompt.
- The Query Bindings tab now has a clear two-mode layout. When the query in context is not yet bound it shows a single **Add ADO query enhancement** card with the query's name and ID (read-only, on one full-width line), an enhanced-view picker, and Save; saving stores the binding with the chosen view's default settings (so navigating away keeps them) and switches the tab into edit mode for that query. Once anything is bound it shows an **Edit ADO query enhancement** card — a dropdown of every bound query, each labelled `{name} ({id})`, plus Delete — alongside a **Query Enhancement Configuration** card holding the enhanced-view picker and its per-view settings and Save. Delete removes the current binding and auto-selects the next one; removing the last binding returns the tab to its empty state.
- Refined the **Work item types** table on the Azure DevOps options tab: a work item type's searchable picker now appears only while adding a new row and collapses to a read-only colored label once you choose the type (remove the row to change it), each row's remove control is now the same compact **×** used for columns, the state field's suggestions reopen immediately after you add a state so you can keep adding without clicking away, and the type/state suggestion lists now float above the table instead of being clipped inside its scroll area (flipping above the field when there is no room below). The options page also uses smaller, window-relative side margins so widening the browser window gives the settings more room.
- Further polished the **Work item types** table: the type picker no longer offers a type already used by another row, a row's per-column add-state fields stay hidden until you pick its type and disappear again once every one of that type's states is mapped, the work-item-type column is narrower, and the ADO state chips in each column can be dragged to reorder them — with the first (primary/default) chip highlighted so it is clear which value gets written back to ADO.
- A fresh install now seeds a fifth board column, **Removed**, after Queue/Active/Waiting/Done, and long work item type names in the type picker show a tooltip with the full name when they are cut off.
- The **Diagnostics** options tab now shows a device-local activity log: the extension records what it does and, in particular, any errors it hits, each line stamped with a timestamp and ordered oldest to newest. A quick **Errors only** filter hides routine informational lines so you can focus on problems, an **Export…** button downloads the shown lines as a timestamped text file, and **Clear** empties the log. The log stays on this device only — it is never synced to your other browsers or sent anywhere.
- Diagnostics log lines are now tagged with the specific part of the extension that wrote them — the feature area (component folder) that owns the code, for example `content/query-page`, `common/settings`, or `options/alerts`, shown in each line — instead of a single broad area name. The Diagnostics tab replaces the earlier component checkboxes with a searchable **Sources** dropdown: type to filter the list of sources, tick one or more to show only those, and use **Select all** / **Clear all** to reset. The extension also records more of its decisions — when it enhances a query page or leaves it on Azure DevOps' own view (with the reason and the signals behind it), when settings or query bindings are saved (names only, never values), and when the top-bar button and menu appear or change — so the log explains not just what happened but why. The AwesomeADO button's menu gains a **View Log** item at the bottom that opens the options page straight to the Diagnostics tab.
- Opening the options page from the AwesomeADO button's menu now reuses an already-open options tab instead of stacking up duplicates: **View Log** and the other menu items focus the existing options tab and switch it to the requested section in place (so **View Log** always lands on Diagnostics even when the options page is already open on another tab), only opening a new tab when none is already open.
- Fixed **Enable Enhanced View** when the options page is already open: it now focuses that tab, switches to the Query Bindings tab, and populates the bind form for the clicked query (query name filled in, with Save ready), instead of just bringing the options tab to the front without showing the binding form.
- A bound query's enhanced view now shows content specific to the view it is bound to instead of a blank page: **Sprint View** and **Project Tracking** each display their own title and a short description of what they will show. The view fills Azure DevOps' content area, keeping the breadcrumb bar and the left navigation rail in place. Switching a query between views, or changing that view's per-query settings, updates the surface in place, and if Azure DevOps redraws the page the enhanced view re-attaches itself.
- The **Appearance** options tab now has **Import / Export configuration**. Export saves your entire AwesomeADO setup — theme, default view, current team name, sprint counts, area paths, board columns, work item types, and every enhanced query (which queries are enhanced and each one's view settings) — to an `AwesomeADO.config` file. Import restores everything from a file you previously exported, replacing your current configuration; a file that is not a valid AwesomeADO configuration is rejected without changing anything.
- Switching a bound query between its enhanced view and Azure DevOps' Standard View from the AwesomeADO button's menu is now a temporary, this-session-only choice: it is no longer remembered or synced. Which view a query shows when a page loads is governed solely by the **Default view** setting, so reopening the browser always returns every query to that configured default.

## 0.1 - Initial scaffolding and basic functionality

- Initial release of the AwesomeADO MV3 extension for Chrome and Edge, including CI/Release pipelines with an immutable release workflow and changelog-validated versioning, and the AwesomeADO icon (an Azure DevOps work-item card with a checkmark and sparkle) shown in the browser toolbar and extensions list.
- Added per-query bindings: each Azure DevOps query can be bound to a view (Sprint View or Project Tracking) with its own settings, so the same view can be configured differently per query. Bindings sync across your devices.
- Added an "Enhance with AwesomeADO" button to the Azure DevOps top bar that appears on any saved query page (bound or not) and opens a popup menu aligned under it. The button shows the extension icon (its purpose stays available as a tooltip and to screen readers) and sits inside the Azure DevOps top-bar command bar alongside ADO's own icons, styled to match them (flat square button with the same hover highlight). On an unbound query the menu offers Options and "Enable Enhanced View" (which opens the options page to bind that query); on a bound query the menu lets you switch that query between its bound view (e.g. Sprint View) and ADO's Standard View, open Options, or "Disable Enhanced View" to remove the binding. The per-query view choice is remembered, synced across your devices, and overrides the global default view.
- Unbound Azure DevOps queries are always left on ADO's own view — the extension only injects its button and never replaces the page until you bind the query. The global Default view applies only to bound queries, and query-page enhancement hides only the content below the top breadcrumb bar, keeping ADO's breadcrumb navigation visible.
- Themeable, tabbed options page (Appearance, Query Bindings, and a Diagnostics placeholder), with a Theme selector (Auto/Light/Dark/Blue, where Auto follows Azure DevOps' own theme), a read-only ADO Configuration panel showing the active tab's organization and project, and a Default view selector (Original ADO View / Enhanced View). The options page header shows the AwesomeADO icon.
- The Query Bindings tab manages per-query view bindings: open it from a query's AwesomeADO button to bind that query (its name is shown read-only), or open it from the button's Options menu to pick from the queries you have open (and any already-bound queries) in a dropdown. Each query can be given an Enhanced View Type, saved, or deleted (unbound), so several queries can each be managed independently.
- The options page detects open ADO Query tabs regardless of which tab is focused, so opening the options tab in the foreground no longer hides the active query's organization and project. It also shows a visible error message when it fails to load or hits an error later, instead of failing silently.
- Auto theme reads Azure DevOps' theme color token instead of the page's white loading fallback, so a Dark ADO account is no longer misread as Light (no options-page white flash).
- The button's "Options" and "Enable Enhanced View" menu items reliably open the options page; failures to open it are now reported instead of being silently ignored.
